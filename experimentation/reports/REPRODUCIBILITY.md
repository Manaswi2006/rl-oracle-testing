## 3. What was run, exactly
Single entry point `python -m src.common.core_train <overrides>` with `configs/common.yaml`; job lists `jobs_stage{0,1,2,3}.txt` (generated by `scripts/gen_jobs.py`), executed by `scripts/run_queue.py`.
Per-run artefacts (HF: `core_extensions_2026/runs/<stage>/<method>/<task>_s<seed>/`): `cfg.yaml` (exact config), `eval.csv` (10-episode evals every 10k steps), `train.csv`, `result.json` (final 50-episode evaluation, accounting, learned-reward diagnostics), `trajectories.npz` (every environment step: obs, action, env reward, success flag, episode id, t, hidden goal*), `preference_labels.npz` (all teacher preference pairs: states/actions, noisy and clean label), `actor.pt/critic.pt/rrm_*.pt`, module checkpoints (`psvm_discriminator.pt`, `facr_models.pt`), `stdout.log`.
(*) stage 0 and stage 1 trajectories were saved as float16 observations/actions without the hidden goal; later runs use float32 plus `goal`.

Arms (all share SAC, 200k env steps, replay 200k, RRM schedule of CoRe: 1k random steps, 19k pre-steps, RRM label rounds every 4k steps, 20 pairs/round, 500 pairs max):
| arm | reward used by SAC |
|---|---|
| `env_dense` / `env_sparse` | MetaWorld dense reward / success flag |
| `core` | (1-a)*FRM + a*RRM, a=0.5 after step 20k (FRM-only before), released final FRM, static |
| `rrm_only` | RRM only (reward 0 before step 20k) |
| `psvm_oracle` | (1-a)*SVM(s,a) + a*RRM, SVM reward = 0.05*clip(logit, +-20) from success-vs-failure visitation discriminator, oracle hard labels |
| `facr_progress` / `facr_value` / `facr_facr` | (1-a)*[progress / success-value shaping / counterfactual advantage] + a*RRM, oracle success flags supply V labels |
| `rrm_extra` | RRM only, +125 extra teacher pairs (label-budget control for the RLF arms) |
| `rlf_<selector>` | RRM only + repair with Q=5 verified candidates per round (+Qpos=2 anchor queries for attack/hybrid/random/disagreement) |

## 4. Deviations from the CoRe setup (all uniform across arms)
1. **No VLM**: RRM preferences come from a scripted teacher on the privileged environment reward with 15% symmetric label noise (`src/common/rrm_scripted.py`). The VLM frame-importance KL term is off. `vlm_queries = 0` everywhere; `teacher_queries` counts simulated queries. Not an exact CoRe reproduction.
2. **FRM**: released final FRM files, no online LLM refinement (the repo would call an LLM at steps 25k/50k/75k/100k).
3. **Budget**: 200k steps (upstream 500k); RRM images 128x128 (upstream 300x300); 10-episode periodic evals, 50-episode final evals on a separate environment instance (seed+1000).
4. **Seeds**: 3 per cell (0-2) for all arms/tasks, plus seeds 3-5 for key arms on Button Press and Hammer (see report). Peg Insert: all learned-reward arms were 0% so extra seeds were not run.
5. Discriminator/value/dynamics networks use state vectors (39-d MetaWorld observation, goal hidden), not pixels; K=200 gradient steps of batch 256/512 every 1000 steps (SVM paper: K=32, batch 64, on images).
6. Speed-only patches: Box repr caching, Adam `foreach=True`, YAML float coercion for learning rates.

## 5. Known limitations / incidents (honest log)
- **Run-level resume only**: runs are idempotent (`DONE` marker, queue skips finished runs) but there are no mid-run checkpoints; interrupted runs restart from step 0.
- Seven stage-1/2 runs and three stage-0 runs were killed and restarted from scratch because they were starved on an over-subscribed GPU (queue placement bug, fixed). Reruns used identical configs/seeds.
- **RLF implementation flaw found after stage 2**: attack/hybrid/random/disagreement selectors never obtained a verified-success reference and therefore added 0 repair pairs. Fixed with anchor queries and a regression test; the original runs are archived in `runs/stage2_noanchor/` and reported separately.
- GPU non-determinism and process concurrency mean reruns are not bit-identical.
- No VLM / paid API was used. Azure/Anthropic credentials present on the host were not used.
